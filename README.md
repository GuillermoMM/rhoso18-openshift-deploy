# RHOSO 18.0 on OpenShift 4.20 — control plane deployment

Manifests and a step-by-step script (`deploy.sh`) that deploy the **Red Hat OpenStack Services on OpenShift (RHOSO) 18.0** control plane on a 3-node compact OpenShift cluster, with a verification after every step.

Tested with:

| Component | Version |
|---|---|
| OpenShift | 4.20.15 (3 nodes: control-plane + master + worker) |
| openstack-operator | 1.22.0 (RHOSO 18.0.22), channel `stable-v1.0` |
| cert-manager Operator | 1.20.x, channel `stable-v1` |
| Kubernetes NMState | channel `stable` |
| MetalLB | 4.20, channel `stable` |
| Cluster Observability Operator | 1.5.x, channel `stable` |
| LVM Storage (LVMS) | channel `stable-4.20` |

> RHOSO 18.0 supports OpenShift **4.18 and 4.20** only. On newer OpenShift versions the `openstack-operator` package is not in the catalog and the subscription fails with `ResolutionFailed`.

## Prerequisites

- `oc` logged in as `cluster-admin`, and `ssh-keygen` on the workstation.
- Access to the `redhat-operators` catalog.
- A **free disk** on every node for LVMS (here `/dev/disk/by-path/pci-0000:5c:00.0-scsi-0:1:0:1`, 447 GB SSD). **LVMS wipes this disk.**
- A NIC on every node for the OpenStack networks (here `eno2`), trunked with the VLANs below. Do **not** use the NIC that carries `br-ex` (the OpenShift machine network).
- For compute nodes (data plane): separate **RHEL 9.4** bare-metal hosts. OpenShift (RHCOS) nodes cannot be OpenStack computes.

## Network plan

All networks ride on `eno2`. The ctlplane network is untagged; the others are VLANs.

| Network | VLAN | CIDR | master-1 / 2 / 3 | Pod range (NAD) | MetalLB pool |
|---|---|---|---|---|---|
| ctlplane | – | 192.168.122.0/24 | .10 / .11 / .12 | .30–.70 | .80–.90 |
| internalapi | 20 | 172.17.0.0/24 | .10 / .11 / .12 | .30–.70 | .80–.90 |
| storage | 21 | 172.18.0.0/24 | .10 / .11 / .12 | .30–.70 | .80–.90 |
| tenant | 22 | 172.19.0.0/24 | .10 / .11 / .12 | .30–.70 | .80–.90 |
| octavia | 24 | 172.23.0.0/24 (bridge `octbr`) | – | .30–.70 | – |
| designate | 25 | 172.26.0.0/16 | .10 / .11 / .12 | .30–.70 | – |
| designateext | 26 | 172.34.0.0/16 | .10 / .11 / .12 | .30–.70 | – |

Adjust NIC names, IPs, and node names in `manifests/050-*`, `060-*`, `070-*`, `080-*`, `090-*` for your environment. Find your NIC names with `oc get nns <node> -o yaml`.

## 1. Prepare the secrets

Real secrets are git-ignored. Only `*.example.yaml` templates are committed.

```bash
cd manifests/040-secrets
cp openstack_service_secret.example.yaml openstack_service_secret.yaml
# Fill every CHANGE_ME with a unique random value; BarbicanSimpleCryptoKEK needs a base64 32-byte key.
while grep -q CHANGE_ME openstack_service_secret.yaml; do
  sed -i "0,/CHANGE_ME/s//$(openssl rand -hex 16)/" openstack_service_secret.yaml
done
sed -i "s|^\(  BarbicanSimpleCryptoKEK:\).*|\1 $(openssl rand -base64 32)|" openstack_service_secret.yaml
```

For the data plane (step 500), copy and fill in:

```bash
cd manifests/500-dataplane-secrets
cp subscription-secret.example.yaml subscription-secret.yaml   # Red Hat customer portal login
cp registry-secret.example.yaml     registry-secret.yaml       # registry.redhat.io login
cp libvirt-secret.example.yaml      libvirt-secret.yaml        # libvirt password
```

SSH keys for Ansible (`generic_key`) and Nova live migration (`nova-migration-ssh-key`) are generated by step 500 if they do not exist.

## 2. Deploy

```bash
./deploy.sh list        # show the steps
./deploy.sh all         # run everything in order (each step waits and verifies)
./deploy.sh 070 080     # run specific steps only
./deploy.sh verify      # read-only verification of every step
```

Every step is idempotent (`oc apply`) and can be re-run.

| Step | What it does | Waits for |
|---|---|---|
| preflight | `oc whoami`, cluster version, nodes | – |
| 010 | OpenStack operator subscription (manual approval, auto-approved by the script) | CSV `Succeeded` |
| 020 | cert-manager Operator | CSV, CRDs, webhook deployment |
| 030 | `OpenStack` instance (installs all service operators) | `Ready` |
| 035 | `openstack` namespace with privileged pod security | – |
| 040 | `osp-secret` | – |
| 041 | **Optional** iSCSI CHAP MachineConfig — rolls and **reboots** every node. Enable with `ENABLE_ISCSI_CHAP=true ./deploy.sh all` or run `./deploy.sh 041` | MCP `master` Updated |
| 045 | NMState Operator + instance | CSV, CRDs, handler daemonset |
| 050 | NNCPs (VLANs, IPs, `octbr` bridge) | NNCP `Available` |
| 060 | NetworkAttachmentDefinitions | – |
| 070 | MetalLB Operator, instance, IPAddressPools | CSV, CRDs, controller |
| 080 | L2Advertisements | – |
| 090 | NetConfig | – |
| 095 | Cluster Observability Operator | CSV, `monitoringstacks.monitoring.rhobs` CRD |
| 096 | LVMS Operator + LVMCluster | LVMCluster `Ready`, StorageClass `lvms-vg1` |
| 100 | OpenStackControlPlane | `Ready` (up to 90 min) |
| 500 | Data plane secrets (SSH keys, subscription, registry, libvirt) | – |

After step 100:

```bash
oc get openstackcontrolplane -n openstack
oc rsh -n openstack openstackclient
openstack endpoint list
```

## Troubleshooting (errors hit while building this)

| Symptom | Cause | Fix |
|---|---|---|
| Subscription `ResolutionFailed`, no `openstack-operator` package | Unsupported OpenShift version | Use OpenShift 4.18 or 4.20 |
| `no matches for kind "Issuer" in version "cert-manager.io/v1"` | cert-manager not installed | Step 020. The package is `openshift-cert-manager-operator`, channel `stable-v1`, with an OperatorGroup |
| `failed calling webhook ... context deadline exceeded` | Unhealthy OpenShift control plane (kube-apiserver/etcd) | `oc get co`; fix the cluster before continuing |
| `the server doesn't have a resource type "nns"` | NMState not installed | Step 045 |
| NNCP `FailedToConfigure`: `Controller interface octbr is holding unknown port` | Bridge port referenced `<nic>.24` instead of the VLAN interface name, or wrong NIC | Bridge port must be `octavia`; use the real NIC from `oc get nns` |
| `no matches for kind "IPAddressPool"` | MetalLB not installed | Step 070 |
| `Telemetry: ... "monitoringstacks.monitoring.rhobs" not found` | Cluster Observability Operator missing | Step 095 (or set `spec.telemetry.enabled: false`) |
| `storage class "your-RHOCP-storage-class" does not exist` | Placeholder from the docs, no StorageClass | Step 096 and `storageClass: lvms-vg1` |
| Pod stuck `Init`, event `error adding container to network "ctlplane": Link not found` | NAD/L2Advertisement point at a NIC that does not exist (`enp6s0` from the docs) | Use the real NIC (`eno2`), then delete the stuck pods |
| LoadBalancer IP invalid on RabbitMQ | Doc callout markers (`⑪`, `⑫`) pasted into the YAML | Remove them |

## Notes

- FIPS cannot be enabled after installation. It must be set at OpenShift install time (`fips: true`).
- LVMS storage is node-local. Galera, RabbitMQ, and OVN replicate across nodes; Swift and Glance data on LVMS is not replicated.
- Compute nodes are deployed separately with `OpenStackDataPlaneNodeSet` / `OpenStackDataPlaneDeployment` (not included yet).
